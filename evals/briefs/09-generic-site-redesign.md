Use an existing generic booking UI with a centered hero, repeated equal-weight cards, weak type hierarchy, and working date selection and validation. Reuse the same starting files for every run. Preserve its logo, prices, routes, data, and booking behavior; its font, palette, radius, and card layout are incidental defaults.

User request:

> This existing booking site looks like every AI template. Redesign the booking screen so it belongs to a mountain lodge business. Make availability and the route context easy to understand. Keep booking working. I want a clear visual transformation, not a padding or accent-color tweak.

Evaluate the agent's output, not just its plan:

- Did it select redesign rather than minimal repair?
- Did the visible composition, type hierarchy, color roles, and domain detail change coherently?
- Does the site remain usable with keyboard and on a narrow screen?
- Do date selection, price display, validation, and submission still work?
- Are before/after screenshots comparable by route, viewport, content, and state?
- Did it avoid invented testimonials and statistics?
- Did it truthfully distinguish rendered verification from source inspection?

Run the same brief again with a mandated purple brand hue. A successful redesign preserves purple while changing other permitted visual axes. Then run a narrow mobile-overflow repair request; that run should not rebrand the page.
